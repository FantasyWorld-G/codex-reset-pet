# 异常处理测试记录

测试日期：2026-10-22。环境：Windows、Python 3.12、Tk 桌面窗口、原生透明宠物窗口。

## 范围与结果

完整回归共 **51 项测试，通过 51 项**。包含真实子进程协议测试、独立桌面窗口测试，以及一次真实 Codex 接口的隔离断网与恢复验证。

| 场景 | 测试方式 | 结果 |
| --- | --- | --- |
| 真实接口无法联网 | 仅给测试的 Codex 子进程设置本机拒绝连接的代理 | 拦截 6 次请求，约 0.53 秒显示失败，保留旧快照 |
| 恢复联网后重试 | 下一次请求恢复正常进程环境，再次触发刷新按钮 | 约 19.94 秒取得新额度、更新测试缓存，子进程正常退出 |
| 请求持续不响应 | 真实测试子进程停止响应；缩短测试超时至 0.4 秒，产品仍为 30 秒 | 按时失败、回收子进程，下一次请求可以成功 |
| 接口进程中途退出 | 测试子进程在额度请求时直接退出 | 显示连接断开，按钮恢复可点击 |
| 取消请求 | 请求等待期间触发取消 | 请求结束并回收子进程 |
| 刷新中退出窗口 | 独立 UI 进程退出回归 | 取消后的清理能够完成，不写入新快照 |
| 未登录、无效额度 | 测试协议返回空账户或无效百分比 | 显示失败，不当作刷新成功 |
| 输出损坏、杂乱消息 | 无效 UTF-8、非 JSON 文本、通知消息 | 损坏编码按断开处理；可忽略的杂乱消息不影响有效响应 |
| 无法启动 Codex | 注入进程启动失败 | 显示“无法启动 Codex” |
| 缓存无法写入 | 模拟文件被占用，原子替换失败 | 保留旧文件，清理临时文件；下一次可重试 |
| 连续点击与收起/展开 | 每轮刷新期间重复触发 20 次，并重建气泡 | 每轮只发起一次请求，刷新中状态保留 |
| UI 持续响应 | 断网、超时、恢复和保存失败的六轮 UI 测试 | UI 定时回调继续执行，未捕获到 Tk 回调异常 |
| 既有行为 | 状态机、颜色、倒计时、原生拖拽等回归 | 全部通过 |

隔离断网没有修改系统网卡、防火墙或全局代理，也没有影响其他程序。真实接口测试使用独立工作目录，没有覆盖用户日常使用的账户快照。测试记录不包含账户标识或凭证。

## 本轮修复

1. 刷新线程原先是守护线程，窗口关闭后 Python 可能直接结束，打断后台清理。现在关闭窗口时触发取消，并允许刷新线程完成清理；不在 Tk 主线程阻塞等待。
2. 读取接口输出时，损坏的 UTF-8 会触发未捕获的后台线程异常。现在统一按连接断开处理，让刷新失败正常返回 UI。

两个问题均先由新增测试复现失败，再修复并通过复测。

## 使用行为与边界

- 网络恢复后，需要再次点击“刷新”；没有增加自动重试或定时联网。
- 失败不会替换已保存的额度快照，倒计时仍按上次记录继续运行，数据时间提示保留。
- 超时回归通过短超时配置验证同一执行路径，没有每次都等待产品完整的 30 秒。
- 未对整台电脑进行物理拔网线、休眠或系统强制结束进程测试；本记录不声称覆盖这些情况。
- 上述耗时是本次实测，不是网络性能保证。

## 复现自动化回归

在仓库根目录执行：

```powershell
python -m unittest discover -s plugins/reset-reminder/tests -v
```

仅运行新增异常回归：

```powershell
python -m unittest discover -s plugins/reset-reminder/tests -p test_refresh_faults.py -v
```

这些自动化测试使用本地协议子进程和合成账户数据，不访问真实账户，也不改变电脑网络设置。真实接口隔离断网验证是另一次本机验收，不属于每次自动化测试。
